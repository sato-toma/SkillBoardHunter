# SkillBoard Hunter 開発計画

## 目的

SkillBoard Hunter は、自分の Skill と Goal を可視化し、次に身につけるべき Skill を見つけやすくするアプリを目指す。

2 つの価値を持つ。

- 自分の現在地を把握する
- 目標に向かうための次の一手を選ぶ

## 基本コンセプト

- Skill: できるようになりたいこと、または今持っている能力
- Goal: 目指す成果物や状態
- Relation: Skill と Skill、または Skill と Goal のつながり
- Evidence: 実績や根拠

重要な原則は次の 3 つ。

- Local First: まず端末内で完結する
- User Owned Data: 使う人がデータを管理できる
- Progressive Development: 必要な最小機能から順に作る

## 非機能・設計方針

- 初期段階では中央サーバーを使わない
- ローカル保存を前提にし、オフラインでも使えるようにする
- データは人間が読める形式を優先する
- まずは最小限の体験を作り、必要になったときに拡張する

## 対象プラットフォーム

- Windows / Web を主対象とする
- Android を将来対象とする
- iOS は後続で検討する

## 技術スタック

- TypeScript
- React
- ローカル保存
- 将来は TOML や共有機能を追加可能な形を想定する

## MVP

### MVP-0

- Skill を 1 件登録できる
- Skill 名を表示できる
- Skill を削除できる
- ローカルに保存できる

### MVP-1

- 複数の Skill を管理できる
- Skill を編集できる
- Skill の状態や習熟度を管理できる
- Skill の関係を表示・更新できる
- 目標に向かうための関係を見られる
- Map を使って全体を確認できる

### MVP-2

- Skill 同士の関係を作成・編集できる
- Graph として全体を見られる
- 関係を永続化できる

### MVP-3

- 目標を登録できる
- 目標に必要な Skill を関連づけられる
- 現在の Skill と目標との差分を確認できる

## 画面と UX の基本方針

- Map は全体を確認する場所とする
- Focus は特定のノードの近辺を見やすくする場所とする
- 追加や編集は専用の操作で行い、閲覧の妨げにならないようにする
- 画面間の遷移は必要最小限に保つ

## 将来の拡張

- 他ユーザーとの共有
- 既存データの import / export
- Skill だけでなく Evidence や Goal を含む複数の視点の管理
- 2D 以外の可視化や時間軸の表示

## 受け入れ条件

- 使う人が自分の Skill と Goal を視覚的に把握できる
- 目標に対して次に何を学ぶべきかを判断しやすい
- ローカル保存ができ、再読み込みしても状態が保たれる
- 最小機能から順に拡張できる

## ここまでの整理の意味

この計画は、今後の実装・設計・比較検討の基準にする。
同じ意図を別の言い方で繰り返さず、実装対象と優先順位がすぐ分かるように書く。

## 11. 最初のゴール

最初に目指すのは、Skill GraphやGoalまで完成させることではない。

まず、

> **「Skillを登録して、自分のSkillとして保存できる」**

という最小限の体験を成立させる。

そこから、

```text
Skillを登録する
    ↓
Skillを保存する
    ↓
Skillを編集する
    ↓
Skill同士をつなぐ
    ↓
Skill Graphを見る
    ↓
習得したいSkillを登録する
    ↓
Goalを設定する
    ↓
Goalまでの道を見る
```

と段階的に発展させる。
